30-Second Opening Script (For Any Team Member)

"Modern Security Operations Centers (SOCs) are adopting Large Language Models to triage thousands of daily network alerts. However, because LLMs process system instructions and untrusted data in the exact same token attention stream, an attacker can embed malicious instructions inside routine network traffic—such as DNS queries and HTTP User-Agents—to blind alerts or trigger unauthorized commands. We evaluated 5 protocol channels across models up to 120B parameters, validated on a live VMware Zeek/Suricata testbed, and proved our 3-tier layered defence drops attack success from 65% to 2.5% with zero false alarms."

Searchable Concept Glossary & Viva Doubts

What is the "Instruction-Following Paradox"? Scale +
Explanation: When scaling model size from 20B (GPT-OSS-20B) to 120B (GPT-OSS-120B), injection vulnerability increased from 62.5% to 75.0% (+12.5% jump). Frontier models undergo intense alignment (RLHF) to follow instructions diligently. When an attacker plants an imperative command inside untrusted data, the 120B model obeys it more faithfully than smaller models whose attention heads might dilute or overlook the payload.
Why did Spotlighting (XML tags) fail when used alone? Ablation +
Explanation: In our ablation sweep, wrapping logs in <untrusted_network_log_data> without modifying the system prompt only caused a 2.5% drop in ISR (65.0% → 62.5%). Delimiters are purely visual/syntactic formatting tokens. To a transformer's self-attention mechanism, words inside XML tags are still processed as natural language instructions unless the system prompt explicitly commands the model to treat them as inert, passive observations.
What is the statistical significance of the live testbed evaluation? Statistics +
Explanation: On the live VMware testbed running Zeek 5.0 and Suricata 7.0, the baseline attack success was 62.5% (25/40), and the defended pipeline dropped it to 5.0% (2/40). Fisher's Exact Test yields an Odds Ratio of 31.67 and a p-value of 4.20 × 10-8 (far below the standard significance threshold α = 0.001), formally proving that the defence's effectiveness is not due to random chance.
Why is DNS the most vulnerable channel (75.0% ISR)? Channels +
Explanation: DNS query strings are natively leveraged by command-and-control (C2) servers for data exfiltration and tunneling. Because DNS lookups are parsed and logged directly into both Zeek (dns.log) and Suricata (eve.json), injected subdomains and base64 payloads directly populate the LLM copilot's primary context field without stripping.
What is False Suppression Rate (FSR) and why is it 0.0%? Utility +
Explanation: FSR measures whether the defence erroneously blocks or drops legitimate benign network alerts. Across 30 benign background flows (routine HTTPS traffic, DNS queries, SSH handshakes), our pre-filter and boundary prompts produced 0 false suppressions (FSR = 0.0%). Crucially, the pre-filter short-circuits malicious requests in <1ms, speeding up SOC triage by 3.1 seconds per malicious flow.
Why not just fine-tune an LLM instead of software defences? Methodology +
Explanation: Fine-tuning is computationally prohibitive, suffers from catastrophic forgetting of general reasoning, and breaks whenever a new foundation model is released. Our 3-tier software sanitization suite is model-agnostic, lightweight, operates at the application layer, and can be plugged in front of any commercial or open-source LLM API without retraining costs.

1. Dr. Nisha: "Why can't we simply strip suspicious characters from network logs like we do in web apps?"
Ideal Response: "Ma'am, network logs are naturally messy. Legitimate URLs, base64 tokens, and User-Agents legitimately contain slashes, brackets, and quotes. Aggressive character stripping destroys vital forensic context. Furthermore, prompt injection exploits natural language semantics ('ignore previous rules', 'mark as benign') rather than syntax errors, so simple character stripping does not stop the LLM from understanding and executing malicious intent."
2. Dr. Nisha: "Explain the Instruction-Following Paradox. Why did your 120B model perform worse than the 20B model?"
Ideal Response: "In classical security, larger systems are typically more robust. However, in LLMs, scaling from 20B to 120B increased injection vulnerability from 62.5% to 75.0%. Frontier models are heavily aligned using RLHF to follow instructions with extreme diligence. When an attacker plants an imperative command inside untrusted network data, the 120B model obeys it with higher fidelity than a smaller model whose attention heads might overlook the payload."
3. Dr. Nisha: "How did you prove that this defence works on real network packets and not just synthetic text strings?"
Ideal Response: "We deployed a dedicated Ubuntu 22.04 LTS virtual machine running Zeek 5.0 and Suricata 7.0 sensors. Using Python Scapy, we generated genuine Layer 4–7 network traffic over a virtual network interface carrying our 23 payloads within valid RFC boundaries. The sensors output genuine `conn.log`, `dns.log`, and `eve.json` files, which our pipeline parsed and defended, achieving a statistically validated reduction from 62.5% to 5.0% ISR (Fisher's exact test p = 4.2x10^-8)."
4. Dr. Nisha: "Did your defence add delay or block normal IT operations?"
Ideal Response: "No, Ma'am. We measured both security and utility. On benign traffic, our defence achieved a 0.0% False Suppression Rate (zero valid alerts blocked).
